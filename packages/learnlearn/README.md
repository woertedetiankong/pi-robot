# pi Curiosity Companion · 好奇心陪伴

让 pi 写代码时，旁边有一张值得想一下的卡片。支持文字、ABCD 选择题、独立追问、最近历史和 Markdown 收藏。想看时展开，返回主任务后追问继续回答，回来还能接着看。

## 安装与启动

需要 Node.js 22+ 和 pi 0.85.1 或更新版本；目前在 pi 0.85.1 上验证。

```bash
# 在本仓库安装为项目级 pi package
pi install . -l
pi

# 或仅为这次会话加载
pi -e ./index.ts
```

源码直接由 pi 加载，不需要构建；开发时再运行 `npm ci`。更新插件源码后重新启动 pi。

默认开启陪伴，使用最多 4 行的摘要。主任务运行时开始生成卡片，也可以 `/companion next` 手动生成。**陪伴复用当前模型发起独立请求，会产生额外用量。** 启动时会显示简短提醒；使用 `/companion economy` 可切到省用量模式，`/companion off` 关闭。

## 日常使用

`/companion` 主菜单只有：**看卡片、下一张（或查看新卡）、最近卡片、暂停自动更新、设置**。

| 入口 | 功能 |
| --- | --- |
| `/companion open` / `Ctrl+Alt+J` | 展开卡片、答题；没有卡片时尝试生成 |
| `/companion next` / `Ctrl+Alt+N` | 下一张：先看较新的历史或待查看卡片，再生成 |
| `/companion previous` | 上一张 |
| `/companion history` | 本次会话最近 20 张，含答案和追问 |
| `/companion chat` | 继续当前卡片的独立追问 |
| `/companion save` | 收藏当前卡片及可选追问 |
| `/companion settings` | 内容、知识库、显示、模型和用量等设置 |
| `/companion on` / `off` / `Ctrl+Alt+H` | 本次会话开启／关闭 |
| `/companion economy` / `standard` | 本次会话切换省用量／标准模式 |

快捷键需要终端支持；不支持时使用命令。普通主任务输入期间不会截获 A、B、C、D。

### 答题与分层讲解

展开后用 **A–D 或方向键**选择，**Enter / 空格**确认，或用 **1–4** 直接作答。**Ctrl+R** 可以直接看答案。

- **知识题**：先显示「正确答案：字母＋选项全文」、你的选择，再解释为什么选正确项、为什么不选错误项，并把结论成立的范围写在旁边。返回摘要仍可见正确答案。
- **取舍题**：列出当前适用的选项，或明确需要额外条件的方案；说明你选的方案如何，不虚构唯一答案。
- **d**：答题后展开／收起补充说明与其他选项分析。新卡片的短例子和图解默认展示，排在所选错误选项的分析之前，不必先按 d；小窗口答题后也会显示 d 和 f 的提示。
- **o**：查看／收起本次引用的原文片段、文件路径和行号。
- **?**：直接进入“没看懂”，可换例子、解释术语、追问原因或检查自己的理解。
- **t**：进入自由追问。
- **[**：上一张；**n**：下一张；**h**：最近历史。
- **s / Ctrl+S**：收藏；**p**：固定／取消固定；**f**：反馈。
- **PgUp / PgDn**：滚动。答案展开后也可用上下键滚动。
- **Esc / q**：返回主任务。

讲解面向初学者：**结论 → 适用范围 → 具体例子与图解**。题干先补必要背景，一张卡只考一个概念；题干、选项和答案都要求说清“谁做什么、实际发生什么”。关键术语首次出现时解释含义，不用陌生术语解释另一个术语。源码题区分当前实现、特定条件和普遍规律，不凭 `fork` 等标识符名字猜测行为。来源不能证明的限制和设计动机不得编造。

新卡片将结论、范围和例子分别保存；缺失或过长时要求模型重写，避免截掉会改变含义的条件。步骤、调用、数据流、并发和分支问题配图，纯定义或事实题不强行画图。`d` 展开进一步说明和其他选项，避免首屏反复复述同一个结论。选择题审校同时检查术语、适用范围、图文一致性和重复内容；真实表达质量仍取决于模型，离线测试验证格式和交互，不能代替真实教学效果评估。

图示保留空格和连线，不自动折行。终端太窄时显示放大提示，周围的白话解释仍可阅读；放大终端后会显示完整图示。收藏为 Markdown 时保留结论、范围、例子、图示和补充说明。更新源码后重启 pi；新生成的卡片采用分层结构，已有卡片保持原布局，追问使用新的讲解要求。

不计分、不倒计时。必要场景条件在答题前可见，补充说明、其他选项分析和原文按需展开。

### 历史与自动更新

本次会话保留最近 20 张卡片，每张独立保存选择、解答、追问、输入草稿和阅读位置。较早的卡片被移出历史时会停止它尚未完成的追问。重启、切换会话或切换会话分支后历史清空；长期保存请收藏。

自动生成不会替换正在显示的卡片：最多准备 **一张待查看的新卡**，提示「有新卡」，然后停止自动请求，直到你查看它。下一张会优先前进到已有历史，避免额外请求。反馈之后可以生成符合新偏好的卡片，旧卡仍保留在历史中。

- 标准模式默认每 120 秒检查是否需要新卡，仅在主任务运行时自动生成。
- 固定、暂停、打开卡片或设置期间不自动生成；离开后重新计时。
- 主任务结束后停止自动出卡并显示完成提示，已开始的独立追问继续回答。
- 省用量模式生成文字卡片，自动间隔至少 10 分钟；手动下一张仍可立即生成。恢复标准模式会继续使用原来的卡片形式和间隔。

### 可以放心离开的追问

追问只显示原卡片的简短标题，把空间留给对话。返回后，后台回复仍写回原卡片；历史和摘要提示新回复，重新进入可看到最新回复和未发送草稿。

| 追问中的操作 | 行为 |
| --- | --- |
| Enter | 发送；回答中可先输入下一条草稿 |
| Esc | 返回卡片，回答继续；再按一次回主任务 |
| Ctrl+X | 明确停止当前卡片的回答 |
| Ctrl+R | 失败或停止后重试上一条，不重复插入问题 |
| Ctrl+S | 收藏卡片及可选追问 |
| ↑ / ↓；PgUp / PgDn | 逐行／翻页滚动对话，不影响输入草稿 |

新回复优先从回答开头展示；等待期间主动翻页阅读前文时，回复到达不会抢走阅读位置。回答中按 Enter 会提示草稿已保留，完成后可再次按 Enter 发送。

失败时保留问题；没有新草稿时会恢复问题到输入框。关闭陪伴、切换会话或分支、移出历史时取消相关请求。追问不会调用工具或把聊天自动发送给主 agent。

### 兴趣与难度反馈

在卡片中按 **f**：

- 这个话题少一点：后续生成尽量减少类似话题。
- 太简单／太难：后续增加推理深度或从基础讲起。
- 解释不清楚：选择“换个例子”“这个词是什么意思”“为什么会这样”或“我的理解对吗”。后三项可输入具体的词、句子或自己的理解，随后进入追问；取消或留空不发送请求。回答中会提示等待，不重复提交。
- 针对性追问先回答你卡住的地方，必要时才补例子和流程图；不要求每次重讲整张卡片。
- 恢复默认偏好：清除本次会话的兴趣和难度调整。

兴趣和难度偏好仅影响本次会话，通过生成提示传给模型。“解释不清楚”只发起当前卡片的追问，不改变兴趣和难度，也不丢弃待查看卡片。不用于计分，也不上传到单独的统计服务。

## 设置与知识库

设置分为：**保存范围、内容、知识库、显示、模型与用量、收藏目录、开启／关闭、重新加载配置**。

### 设置作用范围

设置菜单会一直显示当前范围，默认是 **当前会话**。先选择范围，再修改设置；每次成功应用都有提示。

| 范围 | 写入位置 | 生效方式 |
| --- | --- | --- |
| 当前会话 | 不写文件 | 立即生效，重启后恢复配置 |
| 当前项目 | `<项目>/.pi/companion.json` | 立即生效，后续在这个项目加载；需要项目已受信任 |
| 所有项目的默认值 | `~/.pi/agent/companion.json` | 立即生效；后续加载时项目显式配置仍优先 |

设置 `PI_CODING_AGENT_DIR` 时用户配置改用该目录。只写入本次实际修改的字段，不把继承的项目设置顺带保存为全局默认。收藏只在首次需要时记住收藏目录，不保存其他偏好。快捷命令和电源快捷键只影响当前会话。

项目字段覆盖用户字段；`collections` 按名字合并，同名合集整体覆盖。用户配置的相对目录以配置文件目录为基准，项目配置的相对目录以项目根目录为基准；支持 `~/`。

### 直接添加知识库

进入 **设置 → 知识库 → 添加目录**：

1. 输入 Markdown 目录，可以是 Obsidian vault 内的文件夹。
2. 给合集起一个名称。
3. 插件检查可读笔记，显示篇数和片段数；空目录或读取问题会给出提示。
4. 选择「添加并预览一张」或「仅添加」。预览只使用刚添加的合集，不修改内容模式；预览产生独立模型用量。

添加的合集自动选中，按当前设置范围保存。还可多选已有合集，或检查当前合集。读取 `.md` 和 `.markdown`；可用正文片段至少 20 字符。不依赖 Obsidian 应用或插件，不改写原笔记。

### 显示与内容

- **摘要（默认）**：最多 4 行，标题、一句引子、运行状态和展开入口。生成状态、新卡和新回复不会藏在长正文后面。
- **完整卡片 · 输入框上方**：固定区域展示。
- **完整卡片 · 右侧浮层**：右上角显示，可能遮挡输出；已有明确布局设置继续保留。

终端不足 28 行时改为摘要；浮层还要求至少 96 列。放大后自动恢复所选布局。聚焦后展开可滚动卡片，底部保留操作和状态。

内容模式可选任务相关／知识漫游／混合；形式可选文字／ABCD／混合。混合内容在有合集时交替展示任务相关和漫游，没有合集时使用任务相关；混合形式按两张文字、两张选择题轮换。省用量模式暂时统一为文字。

### 手动 JSON 配置

也可复制 [完整示例](examples/companion.json)，修改后选择「重新加载配置」。仓库带有 [示例知识笔记](examples/knowledge/cache.md)。

```json
{
  "mode": "mixed",
  "format": "mixed",
  "layout": "summary",
  "usage": "economy",
  "selectedCollections": ["软件设计"],
  "collections": {
    "软件设计": {
      "directories": ["./docs", "./knowledge"],
      "include": ["**/*.md", "**/*.markdown"],
      "exclude": ["tasks/**"]
    }
  },
  "saveDirectory": "./.pi/companion-favorites"
}
```

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 开启陪伴 |
| `mode` | `mixed` | `task` / `wander` / `mixed` |
| `format` | `mixed` | `text` / `quiz` / `mixed` |
| `layout` | `summary` | `summary` / `widget` / `overlay` |
| `usage` | `standard` | `standard` / `economy` |
| `intervalSeconds` | `120` | 30–86400 秒，省用量模式实际至少 600 秒 |
| `model` | 当前 pi 模型 | `{"provider":"…","id":"…"}`，`null` 表示跟随 |
| `selectedCollections` | `[]` | 使用的合集名称 |
| `saveDirectory` | 首次收藏时选择 | 独立 Markdown 收藏目录 |

## 数据与运行边界

- 任务相关卡片仅使用当前用户任务（最多 2500 字符），不读取整段主会话或工具输出。知识漫游不附带当前任务。
- 本地检索最多选三个片段发给模型，不发送整个 vault。来源引用仅允许本次提供的笔记 ID，来源带文件路径和行号；模型解读仍需判断。
- AI 选择题先做结构检查，再独立审校场景、选项、答案和解释可读性。不通过最多重写一次并复审，通常两次、最多四次调用，共用 180 秒总时限，并显示生成、审校、重写或复审阶段。省用量通过减少出卡频率和使用文字降低请求量，不绕过选择题审校。
- 检查连续失败时，任务模式使用标明来源的精选暖场题；漫游模式保留现有卡片。请求失败、超时也保留现有内容。
- 忽略隐藏路径、符号链接和 `node_modules`、`vendor`、`dist`。匹配支持 `*`、`**`、`?`，不支持花括号扩展。
- 索引按修改时间刷新，最多 5000 个文件、32 MiB 文件数据；单文件最大 512 KiB，片段最长 2400 字符。过大或不可读文件有提示。
- 卡片生成（含知识库预览）总时限为 180 秒，追问为 45 秒；都有取消和过期结果检查。每张卡片最多一个并行追问；对话最多保留 30 条消息，模型追问使用最近 10 条。
- 打印、JSON、RPC 等非 TUI 模式不启动陪伴。
- 收藏用随机文件名后缀和排他创建，避免覆盖原文件。不会自动整理、改写或上传原笔记。

## 开发与验证

```bash
npm ci
npm run check
npm test
python3 test/smoke.py
node --import tsx test/preview.ts
npm pack --dry-run
```

`test/smoke.py` 使用实际 pi 终端和临时配置，验证摘要、答题、离开后的后台追问、历史、收藏、主任务结束及有作用范围的布局设置。使用离线测试模型，不消耗真实模型额度。测试模型不包含在安装包内。

`test/preview.ts` 输出实际组件的摘要、答题、解答和追问 SVG，位于 `artifacts/`。发布前仍应使用真实模型观察内容质量和等待时间。

扩展接口包括 `KnowledgeSource`（检索／采样／读取）与 `FavoriteStore`（保存卡片和追问）。实现决定及验证交接见 [任务索引](docs/tasks/INDEX.md)。
